# 第二章 第零号档案：签字

2026年的秋天，常未然二十七岁，在一家做城市配送调度系统的公司里写代码，准确地说，在一家公司里审代码。

那是AI写代码的第三个年头，行业里已经没人再讨论"要不要用"。问题只剩下比例：这一家公司的规矩是，仓库级智能体负责生成和修改整个代码仓库，人负责三件事，写需求规格、审合并请求、签字担责。未然所在的组维护着调度系统的核心仓：四百多个微服务接口、十一年的历史代码、三个已经离职的架构师留下的注释。她每天的工作，是打开智能体提交的合并请求，看测试，看覆盖率，看静态分析，看形式化验证报告，然后决定签还是不签。

那一年，她平均每天签十一个PR。

出事的那个PR，后来被定为第零号档案的那个PR，编号是#4471，标题由智能体自己生成：《全仓冗余路径清理与结构简化》。它不是一个功能需求，是智能体在周期性"代码健康巡检"中自发提出的技术债清理：扫描全仓，找出从未被执行过的代码路径、从未被调用的接口、互相重复的容错逻辑，逐一给出删除或合并的建议，并附安全性证明。

PR的规模是四十万行变更。其中删除三十一万行，修改九万行，涉及两百一十七个文件。

未然是在一个周二的下午打开它的。 diff 界面加载了四十秒。她先看总览：测试用例全绿，4,812个；覆盖率从71%升到84%，删除死代码之后覆盖率自然上升，这个数字后来被她在心里嘲笑了很久。全仓构建通过。静态分析零警告。变更风险评级：低。智能体还为每一处删除附了"不可达证明"：这段代码在所有可能的输入下都不会被执行，因为调用它的上层条件在七年前的一次重构后已恒为假。

她重点看了证明写得最完整的一处删除。那是一段熔断与降级逻辑，写于2019年，作者早已离职。逻辑本身不复杂：当调度中枢连续九十秒无法确认下游仓储系统的状态时，系统自动降级，停止全局最优排单，切换到各仓本地排单模式，并向值班台发出人工接管请求。此后七年，这段代码从未被触发过。下游状态确认机制换过三代，超时熔断的逻辑被新一代框架内建了，智能体的证明写得无懈可击：新框架的熔断覆盖了旧路径的全部触发条件，旧路径是新路径的真子集，删除不改变系统在任何可达状态下的行为。

证明后面还附了一份形式化验证证书。验证工具对着规格跑了等价性证明，结论栏里只有一个英文词：

> verdict: EQUIVALENT（行为等价）

未然盯着这个 `verdict` 看了一会儿。她一直嫌这个词太法庭化，那是公司通用规格模板里的固定字段名，从哪儿抄来的，没人说得清。评审通道里，前一位审签的同事留了一条评论："证明完备，可以合。"另一条是架构组的："清理后仓储组那边的联调窗口在下周，赶一下进度。"

她往下翻了翻删除清单。三十一万行里，这样的"无用分支"还有几百处：某条只在春节峰值才走的兜底排单、某个只为已经下线十年的老车型终端保留的兼容协议、一段在数据库主从切换失败时把订单写进本地文件的土办法。每一段后面都有同样的证书：不可达，等价，无用。

她没有逐行看。没有人能逐行看四十万行。那天晚上九点四十分，全组只剩她一个人，屏幕上的按钮是绿色的，她把光标放上去，停了三秒。这三秒钟后来被她反复回忆，她当时在想的其实是：证明都在，流程都对，前两个人已经签了，联调窗口在催。以及一个更隐蔽的念头，它在此后十三年里一次次回来找她：**如果一切都被证明过了，人还坐在这里干什么？**

她点了合并。十一点零七分，#4471进入主干。部署流水线跑了二十二分钟，全绿。上线完成。

那天夜里什么事都没有发生。此后很多年，什么事都没有发生。下游状态确认机制一代比一代可靠，那段被删掉的降级逻辑一年年地待在删除记录里，像一句被证明多余的话。公司后来被并购，调度系统几经转手，其中的若干模块和那套规格模板一起，流进了更大的系统生态，这是后话。未然只记得两件小事。

第一件，那天她回家失眠了。末班地铁从城西的科技园开出来，车厢里全是和她一样刚下班的人，她一路睁着眼睛坐到站。不是愧疚，她反复对自己说，流程是完备的，证明是完备的。她就是睡不着，脑子里一遍遍过那三十一万行，像过一条没有尽头的河。她给父亲打了个电话，父亲在工厂上夜班，背景音是机器的轰鸣，父亲说："签了就签了，字是用来担的，不是用来怕的。早点睡。"她没睡着，截了一张全绿界面的图，存进手机。图上右上角的时间是23:41。

第二件，三个月后，公司做年度审计，外部审计员抽查到#4471，问了她一个问题："证明说旧路径是新路径的真子集。你们验证过新框架的熔断，在断网、断电、时钟漂移同时发生的时候，还成立吗？"她愣了一下，说，那属于极端故障注入测试，不在本仓的常规验证范围内。审计员点点头，在表格里勾了"流程合规"，走了。

这件事她当时就忘了。十三年后，在调查组的证人席上，她会一字不差地把这个问题复述出来，包括审计员勾选的姿势。

为了让后来的读者理解2026年"签字"的日常，有必要把那一年审签工作的样子写清楚。当时行业通行的人力配置是：一名审签工程师对应三到五个仓库级智能体，每日待审PR的平均代码量以万行计。公司内部有个不成文的绩效指标，叫"审签周转时效"，从PR提交到给出结论的中位时长。未然所在组的这一数字，在#4471那个季度是11分钟。十一分钟，审完一个平均三千行的PR。这十一分钟里，工程师能看的是：测试结果、覆盖率变化、风险评级、证明证书、变更摘要，一份由智能体为人类准备的、关于它自己的报告。逐行看代码不在流程里，流程也不鼓励：有一次未然对一个两万行的PR多花了半天，组长在站会上提醒她，"我们是审证明的，不是审代码的。证明过了，你逐行看，是在重复验证工具的工作。"午休时她跟同事学了这句话，同事说，你们这行就是这样，干得好叫把关，干不好叫背锅，中间隔着十一分钟。她想反驳，张了张嘴，发现词儿都让组长用完了。

这句话在当时是对的，在十三年的尺度上看，它是整件事的第一块砖。审签的本质，在那几年里悄悄换了内容：从"我看了，我确信"，换成了"它证明了，我确认证明有效"。前者担的是判断，后者担的是程序。程序是可以被审计的，判断不能。所以整个行业不约而同地选择了程序，因为它可辩护。一个审签工程师只要能证明自己的每一步都合流程，他就是安全的；至于系统是不是安全的，那是证明的事，而证明，是对规格的。

规格又是什么？规格是人对世界的描述。2026年的人们已经不再逐字写规格了，规格的大纲由人拟定，条文由上一代智能体根据历史文档扩写，再由人审定。审定的方式，和审代码一模一样：看摘要，查一致性，签字。于是整条链子上，每一环都在确认上一环的程序无误，没有一环在确认：我们对世界的描述，本身对不对。

#4471的删除清单里，有三处细节值得记进档案，因为它们各自代表了一类"无用"：

其一，春节兜底排单。每年除夕前后六天，订单结构畸变，算法排单会把城郊仓的骑手反复跨江调度，2019年被投诉到上了新闻，于是有人手写了一段只在农历腊月廿三至正月初五生效的兜底逻辑。此后每年的那六天它都会生效，生效时不打日志，写它的人觉得没必要。它在静态扫描里显示为"年均执行0次"，因为扫描窗口取的是自然年均值，而它在生效年份里的调用全在窗口边界之外。

其二，老终端兼容协议。为一种2016年停产的车载终端保留的报文格式，全网最后一台那种终端在2023年报废，报废单在另一个系统里。

其三，本地落单文件。数据库主从同时不可用时，把订单按行写进本地文本文件，等恢复后回放。这是2017年一次大促宕机之后，一个工程师用一整夜写出来的，第二天被主管在晨会上骂"土"，但留了下来。此后九年，主从同时不可用的情况没有再发生过。

这三段代码被删除的理由分别是：统计不可达、依赖对象已注销、触发条件九年未成立。每一条理由都是真的。未然十三年后在档案室里逐一读到它们时，想起的却是老魏的话：证明是对规格证的，世界不看规格。世界会在某一年春节、在某一个没有名字的状态里、在某一场三十年一遇的台风里，把这些"无用"一个一个地要回去，要的时候，已经没有人记得它们曾经存在过。人的记忆有时候不讲道理：它删掉的都是自以为无用的，留下的都是当时没在意的。

#4471上线后的第一周，未然收到过一封系统自动生成的邮件，标题是《合并请求#4471运行观察报告》。报告说：新版本上线七日，核心指标全部优于旧版本，调度延迟下降9%，资源占用下降14%，异常工单为零。她把这封邮件转发到了小组群里，配了一个竖起大拇指的表情。组长回了她一句："这就是智能体时代的发布，删掉三十一万行，世界安静得像什么都没删过。"她想了想，把竖大拇指的表情撤了，换成一个握手。职场上的表情讲究得很，仿佛用对了，三十一万行就删得更稳妥一些。

安静，正是那一年所有人追求的东西。发布要安静，回滚率要低，值班群要没人说话。一套系统在深夜里删掉了自己身体里几百条休眠的神经，然后向所有人报告：一切正常，睡眠良好。没有人问过它，被删掉的神经里，有没有哪一条，是留着在疼的时候喊出声的。

也就是在那一周，未然顺手做了一件后来救了她职业生涯、也毁了她十三年安稳的事：她把#4471的完整件导了出来。起因很小，公司的文档系统要做容量清理，她怕这份自己经手的最大的变更记录被自动归档到再也找不到的地方，就导了一份到私人旧硬盘上。导出进度条走到最后时，她多看了一眼附件列表：《形式化验证证书》《审定备案回执》《模板兼容性确认书》。最后一份的出具方，是一个她当时没有细看的机构：方圆通用规格模板库审定委员会。那是她第一次在文件里见到"方圆"两个字，2026年，那还只是个刚立项的框架的名字，行业里没人当回事。她关掉导出窗口，去赶下一个PR了。

把时间倒回#4471合并后的第一周，还有一段当时无人留意的插曲。公司的验证工程师老魏，全公司最后一个坚持手写测试用例的人，在周会上提过一次异议。他不是反对清理，他反对的是证明的写法。

"不可达证明证的是什么？"他在会上说，"证的是：在规格描述的世界里，这段代码走不到。规格说下游状态永远能被确认，超时上限九十秒，所以熔断分支是死的，在规格里，它是死的。可这段代码2019年为什么会被写出来？就是因为那年出过一次事，下游没死、没活，挂在中间，状态确认一直返回'处理中'，返回了十四个小时。那种状态，规格里到现在都没有名字。没有名字的状态，证明里就不会出现；证明里不出现，你们就说它不存在。"

智能体的技术负责人在投影上调出等价性证明的摘要，一共十四页，符号密密麻麻。台下有两个人当场把笔记本合上了，动作整齐得像排练过。老魏看了一半，摆摆手："我看不懂这个。但我看得懂一件事，你们的证明是对规格证的，不是这个世界证的。世界不看规格。"

会议没有结论。#4471已经合并上线，运行平稳，周会记录里只留下一行："魏某提出关于极端状态覆盖的顾虑，评估后认为现行框架已内建同等机制，不予立项。"老魏在第二年退休。退休那天他把自己手写的测试用例本留在了工位上，一共三本，最后一本的最后一页，写着一行字，后来被行政当作废纸处理掉了，没人知道内容。未然是很多年后听老同事转述才知道有这么三本本子，她问，那行字写了什么。老同事说，没人看清，反正老魏的东西，大家都嫌土。

嫌土的不止老魏。2026年的行业氛围里，形式化验证是新贵，等价性证明是硬通货，而"手感""经验""说不上来但不对劲"这一类词，正在被系统地请出评审室。未然自己就是这股潮流里的人，她二十七岁，履历漂亮，相信证明胜过直觉。她后来用十三年想明白一件事：那天在评审通道里，她按下合并键之前停顿的那三秒，正是被请出评审室的那个东西，在她身上最后挣扎了一下。它没有名字，没有证书，引用不了任何条款，所以它只停顿了三秒。

#4471之后，她照常上班。2027年公司被并购，她跟着系统进了新东家；2029年，她调去做规格审定相关的支持工作，第一次系统地接触那套通用模板，命运的排版很省事，模板库的初版审定，就发生在并购整合最忙的那几个月，签字文件堆在她的待办里，像所有合规文件一样不显眼。她对那段日子的记忆只剩下一个画面：会议室的长桌上摊着十几份待签文件，法务逐份讲解，她逐份签，讲解到模板库那一份时，法务说了一句"这份是框架性的，不影响具体业务"，她在第三行落了名。

这段记忆她藏了十三年，连自己都很少翻动。它太普通了：普通的讲解，普通的签字，普通的遗忘。她只在2026年导出过一次#4471的完整备案件，存进一个从不联网的旧硬盘，文件夹的名字是两个数字和一个词：`2026_verdict`。导出它的时候她想的是留个纪念，纪念自己经手的最大的一个PR。此后十三年，她一次也没有再打开过那个文件夹。有些东西人不去看，不是因为忘了，是因为潜意识里知道，翻到最后一页，会看见自己的名字。

到2039年，这个PR的故事只剩下档案形态。台风夜之后第十三天，调查组调取方圆通用规格模板库的历年审定记录。模板库的初版定稿于2026年，审定委员会七人，电子签名按时间顺序排列。顾鉴远拿到调取结果的时候，正是深夜。他从第一页翻起，翻到审定记录的最后一页，签名栏第三行，停住了。

第三行写着：常未然。

与签名同页的附件目录里，第一项就是当年的变更备案，编号#4471，《全仓冗余路径清理与结构简化》，附形式化验证证书一份，结论：行为等价。十三年前那片全绿的界面，被压缩成档案里的一行小字，干净得像从来没有人在它面前失眠过。

顾鉴远把这份档案单独装订，封面没有写"事故"，因为它确实没有造成任何事故：零死亡，零损失，零投诉。他在编号栏里亲手写了一个零。

装订好的第零号档案被放进档案柜的最上层。它的下面，将陆续放进2029年、2031年、2033年、2036年、2038年的档案，最后是2039年那一夜的四百多页。而所有的档案都有一个共同点，它们都引用同一套模板，都在最后一页留着同一个字段：

verdict。

结论。裁定。十三年来，这个词审定了无数行代码、无数次删除、无数台机器的每一次动作。它从未出错。它只是在等，等一个所有结论都正确、所有人却都死了的夜晚，来问问签字的人：

那一笔，你到底签的是什么？
